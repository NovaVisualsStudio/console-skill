# Nova Ancient Warrior - Android-first prototype

An original third-person 3D action prototype using Godot 4.7.2 and GDScript. Procedural meshes and materials keep the first playable slice free of paid assets.

## Included
- Third-person arena camera and movement with an articulated low-poly warrior assembled from separate body and armor parts.
- Layered humanoid enemies with distinct armor colors and a visible attack telegraph.
- Three escalating arena waves, ending in a larger Ash Titan boss with higher health, heavier damage and a longer windup.
- Three-step sword combo with tuned damage, a wider finisher and hit feedback.
- Directional dodge with a short invulnerability window, plus jump and mobile touch controls.
- Enemy approach, windup, strike and recovery states instead of immediate contact damage.
- Vitality, combo readout, score and victory/defeat states.
- Three data-driven arena regions with distinct floor, sky and lighting palettes.
- Versioned local save profile for best score, earned souls, wave checkpoint, audio preferences and boss/chapter unlock progress.
- Original procedural ambient soundtrack generated at runtime; boss reveal camera sequence.
- Procedural stone arena, pillars, braziers, lighting, sky and lightweight generated audio cues.
- OpenGL Compatibility renderer for broader Android support.

## Controls
Keyboard: WASD or arrows to move, J or Enter to attack, Shift or K to dodge, Space to jump, R to restart.
Touch: directional buttons lower-left; Attack, Jump and Dodge lower-right. A Restart button appears after victory or defeat.

## Run
1. Install Godot 4.7.2 from https://godotengine.org/download/
2. Import this folder as a Godot project.
3. Run scenes/main.tscn.

## Build an Android test APK

The Android ARM64 debug APK is generated by the GitHub Actions workflow `Nova Ancient Warrior Android debug APK`. Open the repository Actions page, choose the latest successful run for this branch, and download the `nova-ancient-warrior-android-debug` artifact. The workflow verifies the APK archive, Android signature and package identifier before uploading it.

This is a debug-signed sideloading build for device testing, not a Play Store release. A successful export still needs an actual phone playtest for touch controls, audio, frame rate and thermal behaviour.

## Verification status
This remains a gameplay prototype, not a finished game. Godot headless validation and the reproducible Android export pipeline are configured; the Android debug APK and on-device playtest must pass before calling the build device-verified. The PS2 port is a separate PS2SDK implementation; this Godot project is not a PS2 ELF.

## Character and mocap pipeline

See [`docs/NOVA_CHARACTER_MOCAP_PRODUCTION_PIPELINE.md`](../docs/NOVA_CHARACTER_MOCAP_PRODUCTION_PIPELINE.md) for the open-source-first production stack, capture protocol, licensing rules and Godot humanoid retargeting contract. The Blender packaging validator is [`tools/blender/export_humanoid_for_godot.py`](../tools/blender/export_humanoid_for_godot.py); it requires a source FBX/GLB with a skinned humanoid, records asset provenance, checks the skeleton/weights/actions, and exports a Godot-ready GLB. No external hero model or mocap take has been imported yet. FreeMoCap requires a desktop capture workstation; the current Android-only target cannot run its full capture pipeline locally.

## Production milestones
1. Validate import and scene execution in Godot 4.7.2.
2. Replace or augment the articulated procedural character with a licensed production-ready rig and authored animation clips.
3. Add animation retargeting, hitboxes, lock-on camera, combat cancel windows, boss patterns and richer feedback.
4. Build authored levels, checkpoints, save data, settings and accessibility.
5. Profile on the target Android phone and tune draw calls, shadows, resolution and memory.
6. Create a separate PS2SDK codebase with a deliberately reduced PS2 asset budget.
